# BD layout on a 1.94 × 2.53 mm outline

This is the smaller-outline rerun of the
[3.93 × 2.53 mm BD layout](gf180-bd-rectangular-pnr.md). It uses the same accepted
generic-MCU mapping (`build/generic-mcu-r10/map-bd`), patched OpenROAD 26Q2,
60% placement-density target and physical recipes. Checkout `baec57b` adds no
RTL changes relative to that run. Only the die width and the macro locations
derived from it change.

The die is **1,940 × 2,530 µm**, or **4.9082 mm²**. The core extends from
(30, 30) to (1910, 2500) µm, an area of 4.6436 mm². The three fixed SRAMs sit at
(100, 1954), (819.35, 1954) and (1540, 1954) µm. Each is 301.300 × 515.810 µm;
all fit inside the core without overlap.

This is a digital-block layout. The 30 µm inset is a core margin, not a pad-ring
allocation. Matching the requested dimensions does not establish shuttle
acceptance, pad/analog fit or physical timing qualification.

## Routed result

Detailed routing completes with **one unresolved Metal2 short**. The report
identifies nets `soc/$abc$1445301$new_n14743_` and
`soc/$abc$1445301$new_n14763_` in the box (1360.6600, 1965.7400) to
(1360.9400, 1966.0200) µm. This is an actual routing failure, not a timing-tool
warning, and it is not waived. The larger comparison run has zero router DRC
violations. This smaller layout is not DRC-clean.

The router reports 5,616,516 µm of wire and 602,004 vias. Its final cell area is
unchanged from global-route repair. The log and `route-drc.rpt` retain the
remaining short. All six flow stages complete, including independent
nominal/minimum/maximum wire RC extractions; completion does not mean DRC or
timing closure.

The [README image](images/bd-layout-1940x2530.png) is the unmodified
2,400 × 3,129 pixel OpenROAD render of `route.odb`, visually checked for the full
outline and all three SRAMs. Its SHA-256 matches the render receipt.

The LEF footprint inventory separates logic from SRAM and physical-only cells.
All areas below are mm². Mapping and pre-placement repair are unchanged:
2.100657 mm² mapped logic and 2.283901 mm² repaired logic.

Placement repair adds 0.404505 mm², CTS 0.050450 mm² and global-route repair
0.149238 mm². SRAM remains 0.466241 mm²; taps/endcaps occupy 0.125372 mm².
Compared with the larger outline, total footprints fall by 0.135196 mm² (3.73%),
while logic grows by 0.006289 mm² (0.22%). The saving is from fewer physical-only
cells, not an RTL area optimization. The current footprint occupies 71.18% of the
die and 75.23% of the core.

Both wire-dependent repair graph proofs and CTS coverage pass. All 26,793
protected native cells and their connections survive; 4,125 periodic storage
sinks remain covered, with the SDA event excluded from CTS and one exclusive
clock driver per SRAM. The clocked storage, guard/allowance/DLYD inventory and
wake workload are unchanged. The separate 0.05 mm² routed-hold-repair reserve
remains unspent.

## Reproduction

Use the existing pinned physical runtime and assets, then run into fresh output
directories:

```powershell
$env:RISCAY_PHYSICAL_TOOLS='P:/Personal/RISCay-MCU/build/control-join-tools.json'
python tools/gf180_pnr.py build/generic-mcu-r10/map-bd build/pnr-bd-1940x2530-r1 `
  --die-width-um 1940 --die-height-um 2530 --placement-density 0.60 --threads 8 `
  --openroad /nix/store/hrxjpkkppbzkcnzf44f60lsm0cj1f4yh-openroad-26Q2/bin/openroad
python tools/render_gf180_layout.py build/generic-mcu-r10/map-bd `
  build/pnr-bd-1940x2530-r1 build/pnr-bd-1940x2530-render-r1
```

The P&R run retains stage databases, graph proofs, clock coverage, electrical
reports and extraction evidence. The image is exported directly from `route.odb`;
the render receipt binds that database, the runtime and the unmodified PNG.
The previous larger run and its image remain historical evidence.
