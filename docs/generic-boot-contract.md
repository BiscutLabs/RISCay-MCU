# Generic MCU boot correction

The generic-MCU correction supersedes both the fixed Groundlark controller and
the proposed ROM power supervisor. This document tracks implementation; unchecked
items are not delivered or qualified.

## Architecture

The RV32E ROM reads a generic image from external SPI storage, feeds its header
and body through the existing loader validation and CRC owner, then starts it.
Blank, incompatible or corrupt storage falls back to I2C upload. The same image
compatibility rules apply to both transports. A transport owns an upload from
BEGIN through completion or abort; another transport cannot splice it.

ROM SPI uses GPIO and a generic peripheral bus claim. Claiming a shared ADC bus
inhibits new conversions and waits for the complete existing transaction to
drain. No flash transaction may overlap ADC ownership. Idle flash CS is inactive.
Profiles cannot change ROM control flow or impose application policy.

POR disables every GPIO output. Watchdog recovery defaults to disabling outputs;
an explicit generic build option may retain output/OE state. Either choice is
independent of profile names and pin labels. The independent watchdog returns the
CPU to ROM; while reset is active, Housekeeping continues its recovery maintenance
kicks. Active, unstarted ROM receives no implicit watchdog lease. Retained image and programming lock follow the existing reset domain
contract. Board pull resistors determine electrical safety while outputs are off.

The programming lock protects supported loader operations, including optional
flash persistence. It is not tamper protection against firmware bit-banging an
externally writable device on ordinary GPIO. Physical write protection requires
the storage device's own WP facility or a separate generic access-control feature.

## Image and ROM ABI

The production build uses a 2,096-byte / 524-instruction RV32E ROM, generated by
`python tools/build_boot_rom.py`. Its audited maximum stack is 56 bytes; SPI boot
requires at least 256 bytes of working RAM. `firmware/boot/rom-report.json` pins
the source and binary hashes. No compiler runs during RTL elaboration. Application
entry is a tail handoff; application startup must initialize its own stack/BSS.

At flash byte zero, ten little-endian 32-bit words are: magic `0x59435352`,
format 1, body length, entry offset, CRC32, ABI `0x00010000`, required working-RAM
bytes, required GPIO mask, required measurement count and image ID. The body
starts at byte 40. The last eight words exactly match I2C BEGIN. CRC32 covers the
body only, using the existing reflected ISO-HDLC algorithm; this is integrity,
not authentication. All fields are validated at full width before narrowing.
`tools/boot_image.py input.bin output.flash --ram 1024 --gpio 7` packs the format.

SPI read uses mode 0, READ `03`, 24-bit addresses and RDSR `05`. The selected
write-through geometry is a NOR device supporting WREN `06`, PAGE PROGRAM `02`
(256-byte pages) and SECTOR ERASE `20` (4 KiB sectors). EEPROM variants with other
write semantics are not supported by this ROM. A busy device is bounded by both
iteration and elapsed-time limits; a stuck boundary cannot receive infinite kicks.
Actual part selection, SPI setup/hold and erase-time limits still need board
qualification.

| MMIO byte offset | Read | Write |
| ---: | --- | --- |
| 76 | Boot status | Error |
| 80 | Boot status; blocks until START or persistence request | 1 BEGIN_OPEN, 2 VERIFY, 3 START, 4 ABORT; 6/7 persistence success/failure |
| 84 | Zero, no side effects | Stream eight BEGIN header words, then aligned body words |
| 88 | SPI claim status: bit0 granted, bit1 ADC busy, bit2 safe release pins | 1 claim, 0 release; release requires CS inactive and SCLK low |
| 92 | Working-RAM top for ROM stack | Error |
| 96..124 | Eight canonical BEGIN metadata words | Error |

Boot status bits: 0 programmed, 1 locked, 2 started, 3 CPU session, 4 program busy,
5 loader hold, 6 persistence pending, 7 persistence succeeded; 15:8 last error,
19:16 streamed header index and 23:21 mode. Command errors use LAST_ERROR; bus
alignment and access permissions remain ordinary MMIO faults. BEGIN_OPEN first
invalidates the old image; only Stored accounts an accepted SRAM write and CRC.
ABORT/reset cannot erase a Stored effect. A host-owned upload and a CPU-owned
upload cannot interleave. Existing I2C BEGIN retains its atomic header semantics.
LAST_ERROR is shared diagnostic state, not a transport-specific completion token.
The ROM checks its retained session, exact header progress and verified completion;
a concurrent rejected host command cannot turn a successful CPU write into failure.

## Recovery, updates and shared pins

I2C ENTER_LOADER (9) sets a retained hold. For a running unlocked application it
suppresses watchdog servicing, including queued kicks, until the independent
watchdog resets into ROM. The delay is bounded by the watchdog interval plus an
already in-flight kick. It never creates a new reset-domain crossing. ROM remains
in the loader until an explicit START; a locked image rejects ENTER_LOADER.
The request is not a GPIO power operation. A normal watchdog reset automatically
restarts a retained valid image (including locked images); the optional I2C-only
fixture retains explicit host START semantics. Crash counting is unchanged.

I2C PERSIST (10) accepts only a verified, unstarted, unlocked image. START, LOCK
and further image mutations reject while pending. ROM erases the old single slot,
writes header/body excluding the magic, reads them back, then writes and verifies
the magic last. A POR before commit leaves an invalid or incomplete slot and
falls back to I2C; this is not an A/B rollback scheme. Application reset retains
an accepted persistence request and ROM retries it. Rejection/read-back failure
keeps the verified RAM image and reports LAST_ERROR 9. Loader word 8 exposes hold,
pending, successful persistence and session/header progress. The persisted bit
means the last explicit write-through succeeded; it does not certify an ordinary
flash-loaded image or subsequent GPIO writes to external storage.

SPI boot assigns logical GPIO3=SCLK, 4=MOSI, 5=flash CS and 6=MISO. SCLK/MISO alias
the ADC's existing physical pads. The physical shell therefore exposes five GPIO
pads for seven logical GPIOs: pad indices 0..4 map to logical 0,1,2,4,5; the mapping
is emitted in `pins.json`. SPI alternate pins 3..6 are excluded from GPIO events
and asynchronous wake demand, while their input values remain readable. ADC
completion uses its own event. Other GPIO events retain their normal behavior.
An external pull-up on flash CS is required while POR/recovery disables its OE.
Even when ordinary GPIO retention is selected, watchdog recovery releases SPI
output pins 3..5. ROM claims the bus before enabling those outputs; the grant
inhibits new ADC starts and waits for the whole native transaction/return to drain.
Release requires flash CS inactive and SCLK low, then queued ADC sampling resumes.
Sampling may pause during boot/update, but sample ages continue and expose staleness.

## Physical scope

The larger ROM mux and changed Control decode are new local timing obligations.
The old three-word ROM response timing is not evidence for the 524-word cone.
Digital simulation is not bundling, hold, synchronizer or external SPI pin timing
qualification. Keep native BD/Click request/return ownership and the full reset
coordinator; do not hide an asynchronous timing problem with a periodic stage.
Full routed qualification remains checklist item 17.
